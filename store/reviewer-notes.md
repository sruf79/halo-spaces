Notes for the reviewer

New in 3.10.0, for the review:
- Quick event window: "Custom…" in Repeat and Alert opens Thunderbird's own dialogs (calendar-event-dialog-recurrence.xhtml and calendar-event-dialog-reminder.xhtml via window.openDialog with their usual arguments); the returned recurrence info and alarms are set on the new event before it is saved. Nothing else is changed.
- Attachments: a menuitem "Quick Look" in the attachment context menu (#attachmentItemContext) dispatches Thunderbird's own "quicklook" event on #attachmentList, which opens Thunderbird's QuickLookManager (macOS, Thunderbird 158+). Hidden when that is not available. Removed on disable.
- The Quick Reply field below messages was removed; its old pref extensions.mailcards.quickReply is cleared at start.
- Settings: the categories in about:preferences are grouped with CSS margins; the Calendar category element is moved before "Privacy & Security" (moved back on disable).

This version supersedes any pending earlier version (3.3.0, 3.5.1) – please review this one instead.

New in 3.6.0, for the review:
- Mail search: before the folder search starts, the add-on asks Thunderbird's own global index (Gloda: Gloda.newQuery(NOUN_MESSAGE).fulltextMatches, terms of three or more characters, waits at most 400 ms) and seeds the hits into the halo search folder; the folder search then runs in two passes (subject/sender/recipients first, then the body) and only adds hits not already listed. Without Gloda (disabled, empty or slow) it falls back to the two-pass folder search. Nothing is sent or changed.
- Quick filter: the Quick Filter bar is never shown; the add-on's filter button and Thunderbird's own commands for the bar toggle the existing quick filter state "unread" (quickFilterBar.filterer, sticky) instead; the bar's menu items are hidden. Restored on disable.
- Sending: while the add-on is active it sets mailnews.show_send_progress = false and mailnews.sendInBackground = true (Thunderbird's own background send via the Outbox); both previous values are restored on disable. Because Thunderbird reports background send failures only in the Activity Manager, the add-on registers an nsIMsgSendLaterListener and shows onMessageSendError as a prompt (Services.prompt.asyncConfirmEx) with a button that opens the Outbox. If Thunderbird does not start sending the queued Outbox by itself (no Outbox existed at startup), the add-on calls Thunderbird's own SendUnsentMessages() after a send (observer "mail:composeSendProgressStop").
- Undo Send (setting undoSend, default 10 s, 0 = off): the add-on listens for the cancelable "compose-send-message" event of the compose window, prevents it, hides the compose window (nsIBaseWindow.visibility) and calls Thunderbird's own CompleteGenericSendMessage() after the delay; "Undo Send" shows the window again. Pending messages are sent before Thunderbird quits ("quit-application-requested").
- Send Later: the message is saved as a draft with the header X-Halo-Send-At (the add-on appends "x-halo-send-at" to mailnews.customDBHeaders so it is indexed); every 30 s due drafts are moved to the Outbox (nsIMsgCopyService) and SendUnsentMessages() is called.
- Remind Me: moves the selected messages to a "Remind Me" folder of the same account and back (nsIMsgCopyService) at the chosen time; the list is kept in the pref extensions.mailcards.reminders. Follow Up only reads the local message databases of Inbox and Sent folders.
- Address book: the personal address book's display name (ldap_2.servers.pab.description) is set once to "Contacts" (localised) only while it still has Thunderbird's default name, and set back on disable/uninstall if it still carries that name. The book is hidden in the sidebar via a data attribute while empty (pref extensions.mailcards.showPersonalAddressBook, menu item in the "…" menu); the last selected contact is remembered in extensions.mailcards.lastContact.
- Sidebars and Today pane: one pointerdown handler on the splitters (pointer capture on the window root) resizes, hides and re-shows the panes; Thunderbird's own splitter handling is skipped for that drag. A 5 px grip element at the window edge shows hidden panes again. Removed on disable.
- Toolbar: the tag button's icon area toggles the starred state of the selected message (Thunderbird's own cmd_markAsFlagged), the dropmarker opens Thunderbird's menu.
- Message list layout "wide" (mail.pane_config.dynamic = 1) is switched once to the classic layout and its menu items are hidden.
- Hover actions now live in the reading pane (see below); the message list capsule and its option are removed.

Also new in 3.5.1 (3.4.0 and 3.5.0 were never submitted):
- Settings category "halo.spaces" in about:preferences (richlistitem in #categories, registered with register_module): its content is the add-on's own options_ui page (options/options.html), embedded in an extension-process <browser> exactly like Thunderbird's add-on manager does it (toolkit inline-options-browser.mjs: messagemanagergroup webext-browsers, remoteType extension, ExtensionParent.apiManager "extension-browser-inserted", ext-browser-content.js). options_ui stays as the second way in. Account Settings and Add-ons and Themes become categories there as well: about:accountsettings and about:addons load in a <browser type="content"> placed over the settings content area of the main window (those pages use `top`, so they can't live inside the settings document). Everything is removed on disable.
- Optional, off by default: "Design without flicker at start" on the options page. When the user turns it on, the add-on writes its own stylesheet (extension/theme.css, with a header line marking it as written by halo.spaces) to <profile>/chrome/userChrome.css and sets toolkit.legacyUserProfileCustomizations.stylesheets = true, because only a profile userChrome.css applies before the first window is drawn. It is rewritten after updates. Turning the option off, disabling or uninstalling deletes that file again and resets the pref (only if halo.spaces had set it). A userChrome.css the user created (without our header) is never overwritten or deleted.
- First install only (existing users are recognised by the add-on's one-time prefs): a welcome window (the add-on's own help window, resource://mailcards/about/halo.html) explains where the options are; the Thunderbird theme is switched to "System theme – auto" (AddonManager, default-theme@mozilla.org) unless one of Thunderbird's built-in themes is already active.
- Reading pane: optional conversation view (on by default, can be turned off): messages of the selected conversation from Thunderbird's global index (Gloda: getMessageCollectionForHeader / conversation.getMessagesCollection), each shown in an about:message browser like Thunderbird's own conversation view (mail.thread.conversation.enabled). Nothing is sent or changed.
- Mailing lists: after a successful one-click unsubscribe the List-ID (or sender address) is remembered locally in extensions.mailcards.unsubscribedLists (max. 500 entries) so the button is not offered again.
- Message list: view and layout combined; the add-on keeps mail.threadpane.listview and mail.pane_config.dynamic in a valid combination (cards only with the vertical layout).
- Increased contrast: CSS for prefers-contrast: more only.
- Event/task dialog (calendar-item-iframe.xhtml): rows are regrouped with CSS order and data attributes only (no DOM moves); the time field gets its own small <panel> with an <input type=time>; the mouse wheel over it changes the value; Thunderbird's keep-duration toggle (#keepduration-button) is set to on and hidden.
- Tasks: the filter radio list of the Tasks space is hidden and offered as a menu button left of the search field; choosing an item calls Thunderbird's own taskViewUpdate(). The same menu switches between a list view (details beside the list: CSS flex-direction plus the splitter's orient attribute; only three columns via treecol.hidden, the table's columns are remembered in extensions.mailcards.taskTableColumns) and the original table view (extensions.mailcards.taskView). The task tree's view is re-linked with tree.refresh() when Thunderbird re-attaches it, because Thunderbird drops the calendar observer when the tree is hidden.
- Reminder window (calendar-alarm-dialog.xhtml): a date icon (month/day, DOM elements) per entry, customtitlebar on macOS so no title bar is shown, window height fitted to its entries; snooze/dismiss are Thunderbird's own buttons.
- Context menus: the "Open in New Tab/Window" items are hidden with CSS, doubled separators are hidden on popupshowing.
- Prompts inside the window (on by default, option "Dialogs inside the window", extensions.mailcards.inlinePrompts): the main and compose windows get a window.gDialogBox object, the same hook Firefox's browser window provides. Thunderbird's own Prompter (Prompter.sys.mjs) then shows window-modal prompts as MODAL_TYPE_INTERNAL_WINDOW inside that window. The object uses toolkit's SubDialogManager (resource://gre/modules/SubDialog.sys.mjs, as Thunderbird's settings do) inside an HTML <dialog> opened with showModal(); prompt content and results are Thunderbird's commonDialog, unchanged. The about:3pane/about:message documents only forward to the outer window's gDialogBox. Removed again on disable.
- Dialog windows without title bar (macOS only, same option): customtitlebar/chromemargin attributes on the event, event summary, folder properties, filter list and filter editor windows, a draggable strip at the top; the window grows by the strip height if its content would be cut off.
- Compose window: a toolbarbutton "Aa" toggles the format toolbar (extensions.mailcards.composeFormatBar); an nsIMsgComposeStateListener (plus a short poll) rewrites the inline-forward header in the editor once: the "-------- Forwarded Message --------" line becomes "Begin forwarded message:", the From row moves first and the date is shown in local time; bodyModified is reset so nothing asks to save. Attachment icons use moz-icon size 32 instead of 16.
- Mail search: before each search the halo search folder's cached hits are cleared in the searched folders (nsIMsgDatabase.refreshCache(uri, [])), because Thunderbird shows stale cached hits until a long search completes.
- Address book: the "Collected Addresses" book row (ldap_2.servers.history) is hidden in the sidebar via a data attribute and CSS (option, default on); the book itself and address completion are unchanged.
- Sidebars: a pointerdown/pointermove listener on the sidebar splitters (calendar, tasks, chat, address book) hides the sidebar with the add-on's own class once it is dragged narrower than 120 px; the width from before the drag is restored on pointerup. The Today pane splitter only hides the pane (Thunderbird's own calendar_toggle_todaypane_command); its width is fixed with CSS.
- Mail search: while the user scrolls the message list (wheel/scroll events) during a running search, the view's nsIMsgSearchSession is paused with pauseSearch() and resumed with resumeSearch() 300 ms after the last scroll event, because the search's time slices on the main thread made scrolling stutter.
- Message list: in card view, a row whose message has the same Message-ID as an earlier row of the same thread (or the root of the preceding thread) gets a data attribute and is hidden with CSS; the messages and the view are unchanged.
- Contact photo dialog (about:addressbook photoDialog): a "Choose…" button that clicks Thunderbird's own file input, a range input that resizes photoDialog._cropRect around its centre, and _redrawCropRect is wrapped to draw a round mask. Saving is Thunderbird's own code; the original function is restored on disable.

halo.spaces is a design add-on (theme + icons + behaviour). It uses one Experiment API, "mailCards" (extension/api/implementation.js), because most of what it does is not possible with WebExtension APIs:

- applies the bundled stylesheet (extension/theme.css) to Thunderbird windows as a user sheet; small global sheets via nsIStyleSheetService: noscroll.css, icon-vars.css, plaintext.css (user sheets) and parts.css (author sheet, only ::part rules – ::part does not apply from user sheets); compose-body.css (user sheet, only the compose editor document about:blank?compose). The editors for event and task descriptions get event-description.css and taskdesc.css as user sheets of that one document (windowUtils.loadSheetUsingURIString)
- reshapes the message list into cards (avatar, preview); hover actions in the reading pane (delete, reply, reply all, forward) call Thunderbird's own commandController of about:message (cmd_deleteMessage, cmd_reply, cmd_replyall, cmd_forward) for the displayed message
- message header: sender picture, folder name next to the date; for mailing lists a note with an "Unsubscribe" button that does nothing until clicked:
  - if the message has List-Unsubscribe-Post: List-Unsubscribe=One-Click (RFC 8058) and an https link, it first asks for confirmation (asyncConfirmEx), then sends one POST "List-Unsubscribe=One-Click" to that link (anonymous, no cookies, response body discarded; redirects after the POST are not followed, a 3xx answer counts as success); if that fails it falls back to the options below
  - otherwise it opens the https link in the default browser via openLinkExternally, or opens a prefilled compose window for a mailto link with the identity the message was sent to – nothing is ever sent automatically
- messages in the system font: plaintext.css, body font only inside message documents (@-moz-document url-prefix imap:/mailbox:/news:), without !important so a message's own fonts win
- spaces toggle, Today pane toggle, an agenda card and a quick event/task window (creates events only through the calendar API when the user confirms)
- a read-only "Birthdays" memory calendar built from address book cards (bday)
- sender pictures: first the photo of the sender's address book card (data: or the local file in <profile>/Photos; an https photoURL, e.g. from CardDAV, is loaded like Thunderbird's own contact view does). Otherwise sender logos (can be turned off in the add-on's preferences: senderLogos): DNS TXT lookup for BIMI (resource:///modules/DNS.sys.mjs) and HTTPS requests to the sender's own domain only (BIMI SVG, apple-touch-icon/favicon, the start of the home page for its <link rel=icon>)
- all network requests go through one function, fetchWithTimeout: an nsIHttpChannel with LOAD_ANONYMOUS (no cookies or credentials), https only, public hosts only (isPublicHttps blocks localhost, IP literals, .local/.lan/.internal and reserved TLDs), every redirect target is checked again in asyncOnChannelRedirect before connecting, and a time limit and a size limit apply to the whole response
- contact photos from the macOS Contacts app (macOS only, off by default; the user turns it on in the preferences or the help window, then macOS asks once for access): runs /usr/bin/osascript with a JXA script that reads only the contact thumbnails, email addresses and names via the Contacts framework and writes them to <profile>/mail-cards-photos/ (index.json + image files); the temporary script file is deleted afterwards. Turning it off stops all reading. Photos stay local and are only shown as avatars
- update check at start (AddonManager findUpdates, at most every 6 hours, respects AddonManager.updateEnabled and the add-on's applyBackgroundUpdates; can be turned off)
- once on first start (marked by a pref, never repeated, existing user customisations are kept): the mail toolbar is set to a compact layout with icon-only buttons and the other spaces get toolbar defaults – only where the toolbar is still at Thunderbird's default; card view rows set to 2 (mail.threadpane.cardsview.rowcount); global search indexing and list view for results turned on (mailnews.database.global.indexer.enabled, gloda.show_as_list_by_default)
- chat message style: while the dark appearance is active and the chat style is Thunderbird's default "mail", the default value (default branch, not the user value) of messenger.options.messagesStyle.variant is set to the bundled "Dark" variant; a variant or style chosen by the user is kept, and the original default is restored on disable/uninstall
- error log: <profile>/mail-cards-debug.log (local only, max 200 KB); detailed entries only with extensions.mailcards.debug = true

Everything is removed again on disable/uninstall (restorers in implementation.js, onShutdown).

No code is minified, obfuscated or loaded remotely. No eval/new Function, no innerHTML (the one built-in SVG icon is parsed with DOMParser).

Build instructions (source code upload):
1. Requirements: macOS or Linux with zsh, python3 (3.9+) and zip – no other tools, no npm.
2. Unpack the source archive and run:  ./build.sh
3. Result: dist/halo-spaces-<version>-atn.xpi is the submitted package (dist/halo-spaces-<version>.xpi is the self-hosted GitHub variant).
The only generated file is extension/theme.css: chrome/merge_spaces.py inserts chrome/spaces.css into chrome/userChrome.css, which build.sh copies to extension/theme.css. For the store package build.sh removes update_url from the manifest and adds strict_max_version from store/max-version.

Test: install (no restart needed; Thunderbird's default theme "System theme – auto"). An automated test runs in a fresh temporary profile: python3 tests/halo_test.py
- optional weather in the Today pane (off by default: extensions.mailcards.weather): HTTPS requests through the same fetchWithTimeout to api.open-meteo.com (current weather code, day/night, temperature for coordinates rounded to 2 decimals) and, only when the user enters a city, to geocoding-api.open-meteo.com; without a city, navigator.geolocation of the main window (the operating system asks for permission). At most every 30 minutes; the last reading is kept in a pref
- fifth space (extensions.mailcards.fifthSpace = chat | addon | web | none, default chat): "none" hides the Chat button; "addon" opens the space of another installed add-on (only spaces registered through the spaces API by a different extension, isExtensionSpace) via gSpacesToolbar.openSpace on the Chat button, its own button is hidden; "web" opens the user-entered http(s) address in a normal contentTab with linkHandler "single-site" (other sites open in the default browser). With fifthSpaceIcon = original the website's /favicon.ico is used as the icon. Values are validated in setSetting (only these choices, only http/https addresses).
