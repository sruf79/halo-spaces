Notes for the reviewer

halo.spaces is a design add-on for Thunderbird on macOS (theme + icons + behaviour). It uses one Experiment API, "mailCards" (extension/api/implementation.js), because most of what it does is not possible with WebExtension APIs. background.js only calls browser.mailCards.start().

At a glance:
- Network: only through one function, fetchWithTimeout (details under "Network access"). Nothing is sent without a user action except sender logos (can be turned off) and the opt-in weather.
- Everything is removed again on disable/uninstall (restorers in implementation.js, onShutdown); changed prefs get their previous values back.
- No code is minified, obfuscated or loaded remotely. No eval/new Function, no innerHTML (the one built-in SVG icon is parsed with DOMParser).
- Source code: the only generated file of our own is extension/theme.css (build steps at the end). One third-party library is bundled: extension/vendor/pst/pst-extractor.js (section 7).


1. Network access

All requests go through fetchWithTimeout: an nsIHttpChannel with LOAD_ANONYMOUS (no cookies or credentials), https only, public hosts only (isPublicHttps blocks localhost, IP literals, .local/.lan/.internal and reserved TLDs), every redirect target is checked again in asyncOnChannelRedirect before connecting, and a time limit and a size limit apply to the whole response.

- Sender pictures: first the photo of the sender's address book card (data: or the local file in <profile>/Photos; an https photoURL, e.g. from CardDAV, is loaded like Thunderbird's own contact view does). Otherwise sender logos (pref senderLogos, can be turned off): DNS TXT lookup for BIMI (resource:///modules/DNS.sys.mjs) and HTTPS requests to the sender's own domain only (BIMI SVG, apple-touch-icon/favicon, the start of the home page for its <link rel=icon>).
- Weather in the Today pane (off by default, extensions.mailcards.weather): api.open-meteo.com (weather code, day/night, temperature for coordinates rounded to 2 decimals) and, only when the user enters a city, geocoding-api.open-meteo.com; without a city, navigator.geolocation of the main window (the operating system asks for permission). At most every 30 minutes; the last reading is kept in a pref.
- Mailing lists: the message header shows an "Unsubscribe" button that does nothing until clicked. With List-Unsubscribe-Post: List-Unsubscribe=One-Click (RFC 8058) and an https link it first asks for confirmation (Services.prompt.asyncConfirmEx), then sends one POST "List-Unsubscribe=One-Click" (anonymous, response body discarded, redirects after the POST not followed, 3xx counts as success). Otherwise, or if that fails, it opens the https link in the default browser (openLinkExternally) or a prefilled compose window for a mailto link – nothing is sent automatically. After a successful one-click unsubscribe the List-ID (or sender address) is remembered in extensions.mailcards.unsubscribedLists (max. 500 entries).
- Fifth space with a web address (extensions.mailcards.fifthSpace = web): opens the user-entered http(s) address in a normal contentTab with linkHandler "single-site"; with fifthSpaceIcon = original the site's /favicon.ico is used as the icon. See section 4.
- Update check at start: AddonManager findUpdates, at most every 6 hours, respects AddonManager.updateEnabled and the add-on's applyBackgroundUpdates; can be turned off.


2. Stylesheets and appearance

- The bundled stylesheet extension/theme.css is applied to Thunderbird windows as a user sheet. Small global sheets via nsIStyleSheetService: noscroll.css, icon-vars.css, plaintext.css (user sheets) and parts.css (author sheet, only ::part rules – ::part does not apply from user sheets); compose-body.css (user sheet, only the compose editor document about:blank?compose). The editors for event and task descriptions get event-description.css and taskdesc.css as user sheets of that one document (windowUtils.loadSheetUsingURIString).
- Messages in the system font: plaintext.css, body font only inside message documents (@-moz-document url-prefix imap:/mailbox:/news:), without !important so a message's own fonts win.
- Increased contrast: CSS for prefers-contrast: more only.
- Optional, off by default, "Design without flicker at start": when the user turns it on, the add-on writes extension/theme.css (with a header line marking it as written by halo.spaces) to <profile>/chrome/userChrome.css and sets toolkit.legacyUserProfileCustomizations.stylesheets = true, because only a profile userChrome.css applies before the first window is drawn. It is rewritten after updates. Turning the option off, disabling or uninstalling deletes that file and resets the pref (only if halo.spaces had set it). A userChrome.css the user created (without our header) is never overwritten or deleted.
- Chat message style: while the dark appearance is active and the chat style is Thunderbird's default "mail", the default value (default branch, not the user value) of messenger.options.messagesStyle.variant is set to the bundled "Dark" variant; a style chosen by the user is kept, the original default is restored on disable/uninstall.
- Context menus: the "Open in New Tab/Window" items are hidden with CSS, doubled separators are hidden on popupshowing.


3. Mail

- Message list: reshaped into cards (avatar, preview). View and layout are combined; the add-on keeps mail.threadpane.listview and mail.pane_config.dynamic in a valid combination (cards only with the vertical layout); the "wide" layout (mail.pane_config.dynamic = 1) is switched once to the classic layout and its menu items are hidden. In card view a row whose message has the same Message-ID as an earlier row of the same thread (or the root of the preceding thread) gets a data attribute and is hidden with CSS; messages and view are unchanged.
- Reading pane: hover actions (delete, reply, reply all, forward) call Thunderbird's own commandController of about:message (cmd_deleteMessage, cmd_reply, cmd_replyall, cmd_forward) for the displayed message. Message header: sender picture, folder name next to the date. Optional conversation view (on by default): messages of the selected conversation from Thunderbird's global index (Gloda: getMessageCollectionForHeader / conversation.getMessagesCollection), each in an about:message browser like Thunderbird's own conversation view. Nothing is sent or changed.
- Attachments: a menuitem "Quick Look" in #attachmentItemContext dispatches Thunderbird's own "quicklook" event on #attachmentList, which opens Thunderbird's QuickLookManager (macOS, Thunderbird 158+); hidden when not available.
- Search: before the folder search starts, the add-on asks Thunderbird's global index (Gloda.newQuery(NOUN_MESSAGE).fulltextMatches, terms of three or more characters, at most 400 ms) and seeds the hits into the halo search folder; the folder search then runs in two passes (subject/sender/recipients first, then the body) and only adds new hits. Without Gloda it falls back to the two-pass folder search. Before each search the cached hits are cleared in the searched folders (nsIMsgDatabase.refreshCache(uri, [])). While the user scrolls the message list during a running search, the nsIMsgSearchSession is paused (pauseSearch) and resumed 300 ms after the last scroll event. Nothing is sent or changed.
- Quick filter: the Quick Filter bar is never shown; the add-on's filter button and Thunderbird's own commands for the bar toggle the existing quick filter state "unread" (quickFilterBar.filterer, sticky); the bar's menu items are hidden.
- Toolbar: the tag button's icon area toggles the starred state of the selected message (cmd_markAsFlagged), the dropmarker opens Thunderbird's menu.
- Sending: while the add-on is active it sets mailnews.show_send_progress = false and mailnews.sendInBackground = true (Thunderbird's own background send via the Outbox). Because Thunderbird reports background send failures only in the Activity Manager, an nsIMsgSendLaterListener shows onMessageSendError as a prompt (Services.prompt.asyncConfirmEx) with a button that opens the Outbox. If Thunderbird does not start sending the queued Outbox by itself (no Outbox existed at startup), the add-on calls Thunderbird's own SendUnsentMessages() after a send (observer "mail:composeSendProgressStop").
- Undo Send (pref undoSend, default 10 s, 0 = off): the add-on listens for the cancelable "compose-send-message" event of the compose window, prevents it, hides the compose window (nsIBaseWindow.visibility) and calls Thunderbird's own CompleteGenericSendMessage() after the delay; "Undo Send" shows the window again. Pending messages are sent before Thunderbird quits ("quit-application-requested").
- Send Later: the message is saved as a draft with the header X-Halo-Send-At ("x-halo-send-at" is appended to mailnews.customDBHeaders so it is indexed); every 30 s due drafts are moved to the Outbox (nsIMsgCopyService) and SendUnsentMessages() is called.
- Remind Me: moves the selected messages to a "Remind Me" folder of the same account and back (nsIMsgCopyService) at the chosen time; the list is kept in extensions.mailcards.reminders. Follow Up only reads the local message databases of Inbox and Sent folders.
- Archive Account Locally (folder pane context menu of an account, not for News/RSS/Local Folders): after a confirmation (Services.prompt.asyncConfirmEx) it copies all folders of that account with their subfolders to Local Folders/<account> (Archive) via MailServices.copy.copyMessages (copy, never move; in parts of 100 messages). Trash, Junk, Drafts, Outbox, Templates and virtual folders are left out. IMAP folders are updated first (updateFolder, waits for "FolderLoaded", at most 60 s). A second run skips folders that already hold as many messages. The same menu item stops a running copy. Nothing on the server is changed or deleted.
- Folder pane context menu: "Mark as Read by Date…" and "Run Spam Controls" call Thunderbird's own cmd_markReadByDate and cmd_runJunkControls (they were only in the menu bar).
- Open Outlook Data File (PST) (File menu, next to Import): the user picks a .pst file with nsIFilePicker; the add-on reads it with the bundled pst-extractor library (section 7) and shows its folders with message counts in an alert. The file is only read (nsIFileInputStream + nsISeekableStream, in pieces, never loaded completely), nothing is written or imported yet.
- Compose window: a toolbarbutton "Aa" toggles the format toolbar (extensions.mailcards.composeFormatBar). An nsIMsgComposeStateListener (plus a short poll) rewrites the inline-forward header in the editor once: the "-------- Forwarded Message --------" line becomes "Begin forwarded message:", the From row moves first and the date is shown in local time; bodyModified is reset so nothing asks to save. Attachment icons use moz-icon size 32 instead of 16.


4. Calendar, tasks, address book, spaces

- Spaces toggle, Today pane toggle, an agenda card and a quick event/task window (creates events only through the calendar API when the user confirms). "Custom…" in Repeat and Alert opens Thunderbird's own dialogs (calendar-event-dialog-recurrence.xhtml, calendar-event-dialog-reminder.xhtml via window.openDialog with their usual arguments); the returned recurrence info and alarms are set on the new event before it is saved.
- A read-only "Birthdays" memory calendar built from address book cards (bday).
- Event/task dialog (calendar-item-iframe.xhtml): rows are regrouped with CSS order and data attributes only (no DOM moves); the time field gets its own small <panel> with an <input type=time>; the mouse wheel over it changes the value; Thunderbird's keep-duration toggle (#keepduration-button) is set to on and hidden.
- Reminder window (calendar-alarm-dialog.xhtml): a date icon per entry (DOM elements), customtitlebar on macOS, window height fitted to its entries; snooze/dismiss are Thunderbird's own buttons.
- Tasks: the filter radio list is hidden and offered as a menu button left of the search field; choosing an item calls Thunderbird's own taskViewUpdate(). The same menu switches between a list view (details beside the list: CSS flex-direction plus the splitter's orient attribute; three columns via treecol.hidden, the table's columns are remembered in extensions.mailcards.taskTableColumns) and the original table view (extensions.mailcards.taskView). The task tree's view is re-linked with tree.refresh() when Thunderbird re-attaches it, because Thunderbird drops the calendar observer when the tree is hidden.
- Address book: the personal address book's display name (ldap_2.servers.pab.description) is set once to "Contacts" (localised) only while it still has Thunderbird's default name, and set back on disable/uninstall if it still carries that name. It is hidden in the sidebar via a data attribute while empty (extensions.mailcards.showPersonalAddressBook). The "Collected Addresses" row (ldap_2.servers.history) is hidden in the sidebar via a data attribute and CSS (option, default on); the book itself and address completion are unchanged. The last selected contact is remembered in extensions.mailcards.lastContact.
- Contact photo dialog (about:addressbook photoDialog): a "Choose…" button that clicks Thunderbird's own file input, a range input that resizes photoDialog._cropRect around its centre, and _redrawCropRect is wrapped to draw a round mask. Saving is Thunderbird's own code; the original function is restored on disable.
- Contact photos from the macOS Contacts app (macOS only, off by default; the user turns it on, then macOS asks once for access): runs /usr/bin/osascript with a JXA script that reads only contact thumbnails, email addresses and names via the Contacts framework and writes them to <profile>/mail-cards-photos/ (index.json + image files); the temporary script file is deleted afterwards. Turning it off stops all reading. Photos stay local and are only shown as avatars.
- Fifth space (extensions.mailcards.fifthSpace = chat | addon | web | none, default chat): "none" hides the Chat button; "addon" opens the space of another installed add-on (only spaces registered through the spaces API by a different extension, isExtensionSpace) via gSpacesToolbar.openSpace on the Chat button, its own button is hidden; "web" see section 1. Values are validated in setSetting (only these choices, only http/https addresses).
- Sidebars and Today pane: one pointerdown handler on the splitters (pointer capture on the window root) resizes, hides and re-shows the panes; Thunderbird's own splitter handling is skipped for that drag. A sidebar dragged narrower than 120 px is hidden with the add-on's own class, the previous width is restored. The Today pane splitter only hides the pane (calendar_toggle_todaypane_command). A 5 px grip element at the window edge shows hidden panes again.
- Narrow windows: when the window gets too narrow (also when toolbar buttons would have to give way), the sidebar of the current space, then the spaces toolbar and the Today pane are collapsed with the add-on's own class and come back when the window is widened again; panes the user hid or showed themselves are left as they are. Which panes were collapsed automatically is kept in extensions.mailcards.autoCollapsed; the Today pane's collapsedinmodes attribute is persisted with Services.xulStore.persist, as Thunderbird does itself.


5. Windows, dialogs, settings

- Settings: category "halo.spaces" in about:preferences (richlistitem in #categories, registered with register_module); its content is the add-on's own options_ui page (options/options.html) in an extension-process <browser>, exactly like Thunderbird's add-on manager does it (toolkit inline-options-browser.mjs: messagemanagergroup webext-browsers, remoteType extension, ExtensionParent.apiManager "extension-browser-inserted", ext-browser-content.js). options_ui stays as the second way in. Account Settings and Add-ons and Themes become categories as well: about:accountsettings and about:addons load in a <browser type="content"> placed over the settings content area (those pages use `top`, so they can't live inside the settings document). The categories are grouped with CSS margins; the Calendar category element is moved before "Privacy & Security" (moved back on disable).
- Prompts inside the window (on by default, extensions.mailcards.inlinePrompts): the main and compose windows get a window.gDialogBox object, the same hook Firefox's browser window provides. Thunderbird's own Prompter (Prompter.sys.mjs) then shows window-modal prompts as MODAL_TYPE_INTERNAL_WINDOW inside that window. The object uses toolkit's SubDialogManager (resource://gre/modules/SubDialog.sys.mjs, as Thunderbird's settings do) inside an HTML <dialog> opened with showModal(); prompt content and results are Thunderbird's commonDialog, unchanged. about:3pane/about:message only forward to the outer window's gDialogBox.
- Dialog windows without title bar (macOS only, same option): customtitlebar/chromemargin attributes on the event, event summary, folder properties, filter list and filter editor windows, a draggable strip at the top; the window grows by the strip height if its content would be cut off.


6. One-time changes and stored data

- First install only (existing users are recognised by the add-on's one-time prefs): a welcome window (the add-on's own help window, resource://mailcards/about/halo.html) explains where the options are; the Thunderbird theme is switched to "System theme – auto" (AddonManager, default-theme@mozilla.org) unless one of Thunderbird's built-in themes is already active.
- Once on first start (marked by a pref, never repeated, existing customisations are kept): the mail toolbar is set to a compact layout with icon-only buttons and the other spaces get toolbar defaults – only where the toolbar is still at Thunderbird's default; card view rows set to 2 (mail.threadpane.cardsview.rowcount); global search indexing and list view for results turned on (mailnews.database.global.indexer.enabled, gloda.show_as_list_by_default).
- The old pref extensions.mailcards.quickReply (removed feature) is cleared at start.
- Error log: <profile>/mail-cards-debug.log (local only, max 200 KB); detailed entries only with extensions.mailcards.debug = true.
- The pref extensions.mailcards.monthScroll (removed feature) is no longer used.
- All other settings are prefs under extensions.mailcards.*.


7. Bundled third-party code

extension/vendor/pst/pst-extractor.js is the npm package pst-extractor 1.12.0 (MIT) with its dependencies long 5.3.2 (Apache-2.0), iconv-lite 0.7.3 (MIT), uuid-parse 1.1.0 (MIT) and browser replacements for Node.js modules (buffer 6.0.3, pako 2.1.0, string_decoder 1.3.0, all MIT/Zlib), bundled unchanged and not minified with esbuild 0.25.10 into one IIFE (global HaloPST). Origin and versions: extension/vendor/pst/SOURCE.md; licenses: extension/vendor/pst/LICENSES.txt. It is loaded only when the user opens a PST file (Services.scriptloader.loadSubScript into its own scope). It has no file or network access of its own: Node's fs is replaced by three functions (openSync/readSync/closeSync) that the add-on provides (PstFs in implementation.js), zlib by pako (inflate only).

To rebuild the bundle (needs Node.js; exact versions are pinned): tools/pst-bundle/build.sh in the source archive; the small shim files it uses are in tools/pst-bundle/.


Build instructions (source code upload)

1. Requirements: macOS or Linux with zsh, python3 (3.9+) and zip – no other tools, no npm (only the optional rebuild of the bundled library in section 7 needs Node.js).
2. Unpack the source archive and run:  ./build.sh
3. Result: dist/halo-spaces-<version>-atn.xpi is the submitted package (dist/halo-spaces-<version>.xpi is the self-hosted GitHub variant).

The only generated file is extension/theme.css: chrome/merge_spaces.py inserts chrome/spaces.css into chrome/userChrome.css, which build.sh copies to extension/theme.css. For the store package build.sh removes update_url from the manifest and adds strict_max_version from store/max-version.

Test: install (no restart needed; Thunderbird's default theme "System theme – auto"). An automated test runs in a fresh temporary profile: python3 tests/halo_test.py
